The project already has a protocol for model-generated material: a
stateless run, one payload whose hash is verified, an anchor-stripped
object, a committed strip script, web off, the wrapper verbatim in the
config. Material produced outside that protocol has never had a
standing declared for it, and the gap is what let three free-form
reports become the object of a ratified item. The rule to write is the
one the anchors entry already states as a sentence and no rule
enforces: anchoring is not absorption. A report enters as a list of
pointers; the pointers are booked, the sources are extracted, and the
report's own prose is never a unit of verification.

The second rule is the one that would have stopped this on day one. An
object that no session can read cannot be the object of a ratified
item, because every finding about it is unfalsifiable in the tree and
only one party can audit it. Held outside the tree is the worst of the
two available states: enough standing to drive an item, not enough to
be checked. If something genuinely cannot be committed, the substitute
has to be named in the rule rather than improvised per item.

The third is the strengthening that has been carried open since the
third recurrence and has now produced its seventh: a verdict that moves
toward a stronger class inside a repair, amendment or addendum pass.
The existing clause diffs a verdict against its body before a review
gate, which does not reach a pass that runs after the gate. Whether the
primary-anchor rule discharges this has been an open operator call
through five handovers; this item settles it either way rather than
carrying it a sixth time.

Three smaller gates fall out of the same run and are cheap. The
scope-envelope stop fires only on overshoot, so a register that came in
far under its own envelope by a declared scope decision passed it
untouched. An instruction that changes a run's task after its final
report is issued currently arrives as an addendum, which is how an
unreviewed reversal rode into a ratifying apply; a new task is a new
run against a new pin. And an artifact drop whose ledger entry is
deferred to a later apply produces exactly the void this incident
opened, so the two belong in one apply.

2026-07-30 amendment (operator-directed; rides the ANN-77..83 chain and
the item-0033 close). The item-0022 disposition closed with a finding
this item's original scope did not carry: a third object class,
alongside the report and the operator-held object -- the source
extract. Its defect mode is the inverse of the first two: not an
unreadable object, but a readable, anchored, in-tree object that
silently misrepresents the primary source it stands for, consumed by
both lanes as if it were the source.

The architectural fact the new rules rest on. The repository does not
re-publish primary-source PDFs -- deliberate, for copyright and
provenance hygiene -- so sources are held by the operator and the
executor lane only, anchored by URL and sha256, never duplicated into
the tree. The extract is therefore the only in-tree representation of
its source, and both lanes consume it: the analysis lane because it has
no source it can open, the executor lane for efficiency. That makes
extract correctness mandatory rather than optional cleanup -- a
defective extract is a silently wrong corpus (ANN-79) -- and it makes
the lanes structurally non-interchangeable on fidelity: no convention
can give the analysis lane a source to check against.

The surrogate-standing clauses. (1) An extract is created or edited
only with its anchored source open, and carries no corpus standing
until an executor fidelity grade against that source over the full
surface: every display, numbered object, citation, quotation and
negative claim, and every prose claim the extract makes about its
source -- the 2d bounces were prose glosses a display-and-quotation
grade could not see (ANN-82), and the first grade's incompleteness is
on record four times over. An extract is re-graded after any change,
and an ungraded or defective extract directs attention at most.
(2) Fidelity is exclusively the executor lane's to establish; an
analysis-lane fidelity assurance is void, and a fidelity question that
arises analysis-side is recorded as open and routed, never answered
there. (3) A session never grades or hashes an artifact it produced or
repaired -- the 2a/2b/2c/2d separation, kept because standing is
conferred by the grade, not by the work. (4) Consumption binds both
lanes: only a graded-clean-and-hashed extract serves as a source
surrogate, no ad-hoc extraction, quotation or paraphrase from a source
bypasses the extract layer, and for the analysis lane the graded
extract is the primary anchor in the rule-19 sense. (5) New or
additional extraction is an operator-gated event -- named anchor line,
purpose, scope -- whose result is graded and newly anchored before
use; a superseding extract re-books its hash with the superseded line
kept as history, per the rule-17 pattern.

The header-design rule (ANN-82, routed here). An extract's provenance
header carries source identity and hash only -- URL with version,
source sha256, declared extraction method and scope -- and never
grade-state or a deixis a later reader cannot resolve ("re-grade
pending", "this session", "at this pin"). Grade-state lives in the
ledger and the grade record, which carry it authoritatively: a header
asserting a fidelity it has not earned is what lets a consumer skip
the check, and a header carrying process-state goes stale the moment
the process moves while the hash forbids the edit. The rule is
prospective; the five hashed CLEAN extracts keep their stale clause,
superseded by the ledger, because editing them would break the
payloads/HASHES.txt one-line-per-file invariant.
