The project already has a protocol for model-generated material: a
stateless run, one payload whose hash is verified, an anchor-stripped
object, a committed strip script, web off, the wrapper verbatim in the
config. Material produced outside that protocol has never had a
standing declared for it, and the gap is what let three free-form
reports become the object of a ratified item. The rule to write is the
one the anchors entry already states as a sentence and no rule
enforces: anchoring is not absorption. A report enters as a list of
pointers; the pointers are booked, the sources are extracted, and the
report's own prose is never a unit of verification.

The second rule is the one that would have stopped this on day one. An
object that no session can read cannot be the object of a ratified
item, because every finding about it is unfalsifiable in the tree and
only one party can audit it. Held outside the tree is the worst of the
two available states: enough standing to drive an item, not enough to
be checked. If something genuinely cannot be committed, the substitute
has to be named in the rule rather than improvised per item.

The third is the strengthening that has been carried open since the
third recurrence and has now produced its seventh: a verdict that moves
toward a stronger class inside a repair, amendment or addendum pass.
The existing clause diffs a verdict against its body before a review
gate, which does not reach a pass that runs after the gate. Whether the
primary-anchor rule discharges this has been an open operator call
through five handovers; this item settles it either way rather than
carrying it a sixth time.

Three smaller gates fall out of the same run and are cheap. The
scope-envelope stop fires only on overshoot, so a register that came in
far under its own envelope by a declared scope decision passed it
untouched. An instruction that changes a run's task after its final
report is issued currently arrives as an addendum, which is how an
unreviewed reversal rode into a ratifying apply; a new task is a new
run against a new pin. And an artifact drop whose ledger entry is
deferred to a later apply produces exactly the void this incident
opened, so the two belong in one apply.

Scope guard: this item writes rules and does not re-adjudicate any
verdict. The re-grading belongs to the disposition item.
